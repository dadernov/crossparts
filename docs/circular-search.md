# Скрытый круговой поиск

По умолчанию выключен. Переключателя в интерфейсе и параметра в публичном
запросе нет. Настройка применяется к одиночному поиску и обработке Excel.

## Быстрое включение

В `/root/crossparts/.env.production` установить (или добавить):

```dotenv
CP_CIRCULAR_SEARCH_ENABLED=true
CP_CIRCULAR_SEARCH_MAX_QUERIES=6
CP_CIRCULAR_SEARCH_MAX_QUERIES_PER_SOURCE=2
CP_CIRCULAR_SEARCH_TIMEOUT=20
```

Затем выполнить `sudo systemctl restart crossparts`.
Для отключения установить `CP_CIRCULAR_SEARCH_ENABLED=false` и снова
перезапустить сервис. Для локального запуска настройки задаются в `.env`.
Изменение файла без перезапуска не применяется.

## Поведение и ограничения

1. Выполнить обычный поиск исходного номера в выбранных каталогах своей группы.
2. Собрать уникальные номера OE/OEM и aftermarket из успешных ответов.
   Удалить разделители, исключить исходный номер, стандарты WVA/FMSI и шум.
3. Искать эти номера только в каталогах, ответивших `not_found`.
   Каталоги с `blocked`, `error` и `ok` повторно не опрашиваются.
4. Завершить поиск в каталоге после первого успешного ответа с кроссами,
   блокировки или ошибки. Новые кроссы второго прохода не запускают третий.
5. Объединить найденные кроссы обычным способом, сохраняя каталог-источник.

Бюджет — максимум 6 дополнительных вызовов адаптера на исходный номер,
не более 2 на каталог, до 20 секунд на весь второй проход. Оба числовых
лимита можно установить в 0 для пропуска второго прохода.
Вызов адаптера может включать несколько HTTP-запросов за карточками товаров;
лимит не означает 6 отдельных HTTP-запросов. Сохраняются ограничения
параллельности каталогов и числа карточек `CP_MAX_PRODUCTS_PER_OE`.
Кандидаты берутся в порядке ответов выбранных каталогов и их кроссов;
сначала первый кандидат для всех пустых каталогов, затем второй.
При большом количестве кроссов это намеренно неполный поиск.

Кэш читается и записывается по паре «каталог + фактически запрошенный номер».
Расширенная выдача не записывается как прямой ответ на исходный номер.
Таймаут второго прохода сохраняет результаты первого и уже завершённых
дополнительных запросов. Дополнительные обращения не списывают отдельные
поисковые позиции аккаунта: единицей остаётся исходный номер.

При включённом режиме ответ агрегатора (и API одиночного поиска) содержит
`circular_search.attempts`: каталог, номер, статус, число кроссов и сообщение
каждой дополнительной попытки. Это поле не сохраняется в истории заданий.
В отчёте успешно дополненного каталога будет сообщение
`Найдено через кросс <номер>`, в том числе в сохранённом отчёте задания.
Прямые отчёты остальных каталогов остаются исходными; ошибки второго
прохода отражаются в `attempts`.
