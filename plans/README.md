# Планы CrossParts

## Каталоги и парсинг

[catalogue-expansion.yaml](catalogue-expansion.yaml) — план поэтапного подключения ресурсов из «Ресурсы для парсинга.xlsx»: четыре раздела, отдельный выпуск каждого источника/группы, эталоны точности, тесты всего пути поиска, производительность, staging и безопасный откат.

[catalogue-resource-inventory.yaml](catalogue-resource-inventory.yaml) — построчная сверка всех 47 ресурсов: 33 бренда, 34 логических источника, 13 существующих адаптеров и 21 отсутствующий. Сохранены исходные значения и номера строк Excel. Исторические статусы из кода не означают свежую проверку доступности.

[../PARSING.md](../PARSING.md) — объяснение текущей реализации простым языком, обнаруженных ограничений и порядка работ.

Статус: **реализация идёт в отдельной ветке `catalogue-expansion`**. P01–P02 завершены: инвентарь проверяется автоматически, pytest всегда использует временную БД, offline-набору запрещена внешняя сеть. P03 выполняется. Production, его настройки и рабочая база не менялись; выпуск разрешается только отдельным поручением после release report по G7.

## Публичные SEO-страницы

[seo-public-pages.yaml](seo-public-pages.yaml) — машиночитаемый план публичных SEO-страниц: содержание, данные, маршруты, переход в поиск, авторизация, индексация, аналитика, тестирование и выпуск.

Статус: **только план**, реализация не начата. Прочитан код на коммите `ecf02f1`, дата подготовки — 22 сентября 2026 года.

Для продолжения достаточно поручения: «Реализуй `plans/seo-public-pages.yaml`». Исполнитель сначала сверяет актуальный код и границы поручения, затем идёт по `execution.tasks` с учётом `depends_on`, обновляя `status`, `evidence` и `actual_changes`. Доступы к аналитике и подтверждённые данные отмечены в `inputs`; отсутствие данных не разрешает их выдумывать.

Рекомендуемый пилот: существующий `/categories`, пять страниц групп и 5–10 проверенных карточек номеров. Проектируемые файлы и команды в YAML ещё не существуют; это задания для будущей реализации.
